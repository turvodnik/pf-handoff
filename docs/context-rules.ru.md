# Бюджет контекста и непрерывность сессий — полные правила

*[English version](context-rules.md)*

> Ручной русский перевод генерируемого `docs/context-rules.md` (канон — `skills/pf-handoff/references/context-rules.md`, английский).
> Обновляется при релизе; `sync-from-tools.sh` предупреждает, если число разделов разошлось.


Справка для агента. Краткие указатели живут в глобальных правилах (§13); здесь — детали. Читать при работе с порогами окна, стаями субагентов и планировании крупных кусков.

## Слои памяти

- Живое состояние задачи — HANDOFF-файл `.agents/runtime/handoff/YYYY-MM-DD-<slug>.md` проекта (в .gitignore).
- Проектная память — журнал решений и task-пакеты.
- Постоянная — MEMORY.md, CLAUDE.md/AGENTS.md, база знаний. MCP-серверы памяти не используются: файлы читает любой агент, это дешевле и без supply-chain-риска.

## HANDOFF-файл

Шпаргалка состояния, по которой любую сессию можно продолжить без потерь (шаблон — `references/handoff-template.md` этого скилла).

- Frontmatter: `status: active|closed`, `session_id`, `task` (идентификатор тикета, у владельца — `T-###`, либо «—»), `updated`.
- Разделы: Цель / Состояние (сделано и чем доказано) / Следующий шаг / Блокеры и вопросы / Ключевые файлы и решения / Не делать (отменённые направления).
- Всегда перезаписывается целиком, ≤120 строк. Сменилось решение — обнови немедленно; отменённое — одной строкой в «Не делать».
- Одна задача = один файл. Сменилась задача — закрой старый (`status: closed`; вернёшься — `pf-resume <slug>` переоткроет) и заведи новый: чужое в свежую сессию не тянется.

## Мультиагентность и стаи субагентов

- HANDOFF пишет владелец задачи (owner тикета), остальные агенты только читают.
- Субагенту — файловый выход: ПОЛНЫЙ результат в файл/тикет (ничего не теряется — важно для фокус-групп и исследований), в чат родителя — короткая сводка, а не простыня (окно оркестратора — самый дорогой ресурс).
- ПЕРЕД запуском волны — чекпоинт HANDOFF с реестром «агент → задача → файл результата → статус»; каждому в промпт явно: «полный результат в файл <путь>, в ответ — сводка ≤15 строк». Принял результат — отметь в реестре.
- Правила одинаковы на любой глубине (внуки и глубже); субагент, ведущий свою волну, держит реестр в своём файле прогресса (тикет/workspace).
- Стая в полёте при порогах окна: новых волн не запускать, только принимать. Компакт посреди ожидания ничего не теряет: результаты лежат в файлах и транскриптах агентов, уведомления о завершении доходят и в сжатую сессию — реестр говорит, чего ещё ждать и зачем. Оборвавшийся уровень заменяется преемником: тот продолжает по реестру и файлам результатов, принятое не переспрашивая.

## Пороги окна

Проценты от контекстного окна любого размера. Claude получает их автоматически хуками; агенты без хуков следят сами по вехам.

- до 60% — работать свободно, HANDOFF обновлять на вехах;
- 60% — чекпоинт HANDOFF; новые крупные куски — субагентам (в главное окно возвращается только сводка) или в новую сессию;
- 80% — новых средних и крупных (M/L) кусков не начинать; довести текущий до проверяемой точки, чекпоинт;
- 90% — немедленно полный `pf-handoff`; дальше только мелочи; автокомпакт — штатная страховка, со свежим HANDOFF он безопасен.
- Оценка «влезет ли»: кусок не должен стоить больше половины остатка окна. Ориентиры: разведка кода 30–80k токенов, средний (M) кусок 100–250k, крупный (L) — только свежее окно или субагенты.
- Пороги проекта переопределяются файлом `<проект>/.agents/context-budget.json`: `{"thresholds": [50, 70, 85]}` (три целых по возрастанию; нет файла или он кривой — дефолт 60/80/90).

## Чекпоинты

На вехах, при пересечении порогов, перед долгими рискованными шагами. Закрытие сессии — через `pf-handoff` (сверка → журнал → статусы).

## Памятка человеку («когда что нажимать»)

Автомат — ничего (агент чекпоинтит сам, автокомпакт + хук подхватят); почистить окно, оставаясь в чате — `/compact`; пауза — `/pf-handoff`, потом просто продолжать; закрыл терминал — `claude --continue`; новый чат — `/pf-resume`; начисто в том же окне — `/pf-handoff` → `/clear` → `/pf-resume`; несвязанная новая задача — `/clear` без resume.
