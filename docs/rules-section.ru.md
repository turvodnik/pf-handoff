# Раздел правил «Бюджет контекста и непрерывность сессий»

*[English version](rules-section.md)*

Вставьте текст ниже в ваш `~/.claude/CLAUDE.md` (или канонический AGENTS.md). Он намеренно короткий: всё отсюда грузится в **каждое** окно на старте, поэтому здесь только инварианты, которые обязаны действовать даже без загруженного скилла. Полные правила лежат в файле, который агент читает по требованию: `~/.claude/skills/pf-handoff/references/context-rules.md` (едет вместе со скиллом) и [`context-rules.ru.md`](context-rules.ru.md) в этом репозитории.

Скиллы pf-handoff/pf-resume ссылаются на этот раздел как на «§13» — если у вас своя нумерация разделов, число можно поменять, суть ссылок от этого не страдает. Упоминания «журнала» и «task-пакетов/тикетов» — это файловый протокол исходной системы владельца; если у вас их нет, читайте как «заметки проекта» и «ваш трекер задач».

## 13. Бюджет контекста и непрерывность сессий

Живое состояние задачи — HANDOFF-файл `.agents/runtime/handoff/YYYY-MM-DD-<slug>.md` проекта (в .gitignore); проектная память — журнал решений и task-пакеты; постоянная — MEMORY.md, CLAUDE.md/AGENTS.md, база знаний. Полные правила (формат HANDOFF, мультиагентность и стаи, чекпоинты, памятка человеку) — скилл `pf-handoff`, `references/context-rules.md`; агенты без этого скилла читают файл напрямую: `~/.claude/skills/pf-handoff/references/context-rules.md` (либо `~/.codex/skills/…`, `~/.gemini/skills/…`).

Всегда, даже без загруженного скилла:
- **Пороги окна** 60/80/90% (60 — чекпоинт HANDOFF, крупное — субагентам; 80 — новых M/L-кусков не начинать; 90 — немедленно полный `pf-handoff`). Claude получает пороги хуками, агенты без хуков следят сами по вехам. Переопределение — `<проект>/.agents/context-budget.json`: `{"thresholds": [50, 70, 85]}`.
- **Стая субагентов**: перед волной — чекпоинт HANDOFF с реестром «агент → задача → файл результата → статус»; субагенту — полный результат в файл, в чат родителя — сводка ≤15 строк.

**Инструкция компактору** (действует при /compact и автокомпакте): при сжатии истории обязательно сохранить — текущую цель и задачу, путь к активному HANDOFF-файлу, последние принятые решения и отклонения от плана, незакрытые критерии приёмки, список «Не делать». Отбрасывать: содержимое прочитанных файлов, сырые выводы команд, отработанные ветки рассуждений.
