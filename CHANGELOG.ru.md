# Журнал изменений

*[English version](CHANGELOG.md)*

Semver: ломающие изменения (формат HANDOFF-файла, имена state-файлов, контракт скиллов, схема установки) = major; новые возможности = minor; починки = patch.

## [2.0.1] — 2026-10-12

### Исправлено

- `precompact.sh` больше не печатает в stderr `warning: command substitution: ignored null byte in input`, когда во входе есть нулевой байт (NUL), под bash 4.4 и новее (Linux). Заглушено только чтение входа хука, поэтому вход, который не является данными Claude, проходит молча, как описано в 2.0.0. Настоящие данные Claude обрабатываются так же, как раньше. Из-за этого предупреждения набор тестов 2.0.0 был красным в CI на Linux; в macOS стоит bash 3.2, он отбрасывает байт без предупреждения.

## [2.0.0] — 2026-10-12

Major по правилу semver выше: пороги окна по умолчанию меняются с 60/80/90 % на 40/60/75 %, а файл порогов на проект больше не читается (контракт настройки); `pf-handoff` при закрытии сессии больше не сливает, не пушит и не удаляет ветку (контракт скилла); установщик оставляет запись хука или статус-строки, указывающую в другое место, вместо того чтобы её перезаписать (схема установки).

### Ломающие изменения

- **Ломающее: пороги окна — 40 / 60 / 75 % окна модели** (были 60 / 80 / 90 %). На 40 guard просит короткий чекпоинт HANDOFF, на 60 — полный `pf-handoff` (и пишет снимок состояния), на 75 — финальный handoff. Единственное переопределение — переменная окружения `CONTEXT_GUARD_THRESHOLDS`: три целых от 1 до 99 по возрастанию через пробел, например `"30 50 70"`; любое другое значение молча даёт дефолты. Цветовые зоны статус-бара следуют тем же значениям (жёлтый с первого, красный со второго) и больше не «зелёный < 60 % / жёлтый 60–79 % / красный ≥ 80 %». Сжатие платформы по-прежнему вне хуков: 80 % окна 1M, 90 % окна 200k (`/autocompact 800000`, `/autocompact 180000`).
- **Ломающее: закрытие сессии больше не интегрирует ветку.** Шаг 6 `pf-handoff` раньше сливал рабочую ветку `--ff-only`, удалял её worktree и ветку. Теперь он только записывает в HANDOFF ветку, путь worktree, SHA HEAD и «не слито, ждёт приёмки»; при незакоммиченном — останавливается. Слияние, push и удаление — отдельное явное действие с названными условиями (`skills/pf-handoff/references/branch-closing.md`).
- **Ломающее: установщик оставляет чужую регистрацию хуков.** `hooks/install.sh` раньше переводил на этот клон каждую регистрацию, и `statusLine` тоже. Теперь запись хука или `statusLine`, команда которой называет существующий файл вне этого клона (другая копия этих хуков, чекпоинт мастерской автора, ваш собственный скрипт статус-строки), остаётся как есть, а установщик печатает `KEPT: <событие> → <путь> (registered elsewhere; re-run with --force to point it at this clone)`. Команда `statusLine`, в которой вообще нет файла (`npx ccusage statusline`), тоже остаётся. Путём считается слово, начинающееся с `/`, `~`, `./`, `../` или `$` (`$HOME`/`${HOME}` раскрываются). Регистрация на отсутствующий файл по-прежнему чинится. `bash install.sh --force` переводит всё на этот клон. `doctor.sh` считает оставленную запись исправной (rc 0) и называет путь или команду. Если вы ставили более раннюю версию: прежний установщик заменял вашу `statusLine`; прежнее значение лежит в **самом раннем** бэкапе `<файл настроек>.bak-<YYYYMMDD-HHMMSS>`, сделанном до первой установки pf-handoff (в более поздних уже наша строка), — верните блок и запустите `install.sh` снова.

### Удалено

- **Файл порогов на проект `<проект>/.agents/context-budget.json`** (v1.10.0 описывал его в README, раздел «Настройка») больше не читают `context-guard.sh` и `statusline.sh`; оставшийся файл игнорируется. Используйте `CONTEXT_GUARD_THRESHOLDS`.

### Изменено

- **`context-guard.sh`: субагентам директив нет.** Директива велела субагенту сделать чекпоинт HANDOFF, который принадлежит владельцу задачи; 139 из 146 субагентов её игнорировали. Субагента узнают по `agent_id` во входе хука или по его собственному транскрипту в `subagents/`; для него ничего не читается и не пишется.
- **`context-guard.sh`: окно берётся из модели.** Его читают из модели последнего ответа в транскрипте, а не из алиаса `/model` в настройках (с алиасом `opus` guard принимал 200k за окно модели 1M и объявлял ложные «90 %»). Сначала берётся окно, которое последним сообщила статус-строка (число самого харнесса); если его нет — для моделей семейства 5 предполагается 1M; для любой другой — окно, которое guard оценил раньше, иначе 1M. `CONTEXT_GUARD_DEBUG=1` печатает одну строку: какое окно использовано и откуда оно взято.
- **`context-guard.sh`: прыжок через второй порог всё равно пишет снимок.** Один крупный результат инструмента, поднявший контекст с 59 или 79 % сразу до 95 %, раньше попадал в последнюю зону без снимка; теперь снимок следует за первым пересечением второго порога.
- **Исправление: ход с серверным инструментом `advisor` читался как удвоенный контекст.** API сообщает такой ход несколькими итерациями (основная модель → advisor → основная модель), а usage верхнего уровня — их сумма, примерно вдвое больше настоящего контекста (одна сессия: 515 357 → 1 033 942 токена за один ход). Харнесс, статус-строка и guard читали эту сумму, поэтому guard перескакивал с 51 % на «100 %» и пропускал второй порог. Теперь guard читает последнюю итерацию основной модели.
- **`precompact.sh`: чужой вход ему не принадлежит.** Вход без ключа `"session_id"` (мусор, payload другой платформы) теперь завершается кодом 0 без вывода и без строки в журнале; payload формы Claude, который не удалось разобрать, по-прежнему блокирует. `autocheckpoint.sh`, вызванный без `--session`, молча выходит с кодом 0, пустой `--session` остаётся ошибкой. Каждая строка `OK` в `compacts.log` теперь заканчивается на `guard announced t2: yes|no|unknown`, чтобы ретро могло посчитать сжатия, которых guard не предвидел.
- **`sessionstart.sh`.** После сжатия (автоматического или ручного) и при резюме первая строка — «прочитай HANDOFF и продолжи»: собственный файл агента по `session_id`, иначе самый свежий без session id, со списком; перечисляются задачи автопилота, которые в его реестре ещё помечены как запущенные. После ручного `/clear` хук только указывает на файл (`/pf-resume <slug>`). На свежем старте хук только перечисляет активные файлы с указателем `/pf-resume <slug>` — продолжать ли, решает человек; задачи реестра надо сверить, а не считать ни мёртвыми, ни живыми. Сессия в каталоге, который не проект (нет ни `AGENTS.md`, ни `.agents/`), получает предупреждение, что снимки и заявки уйдут в глобальные папки.
- **Установщик: вручную увеличенный таймаут хука переживает переустановку** (раньше он сбрасывался на 10 с при каждом `git pull && bash install.sh`).
- **`claims-check.sh`.** Заявка может нести сессию как `sid:<8 hex>` в поле «кто»; `--sid <8hex>` (или `CLAIMS_SID`) превращает пересечение со строкой той же сессии в `СВОБОДНО (своя)`, битый sid — `ВНИМАНИЕ`. `--sweep` показывает истёкшие строки заявок (`--sweep --yes` переносит их в `claims-archive.md`). Живая проверка читает весь файл после шапки и разбирает маркер списка `- ` и поле `СНЯТА` так же, как свип. Составная область (`a + b`, `{a,b}`, `a, b`, глоб) раскладывается на отдельные пути, и каждый проверяется сам. Каждый запуск дописывает одну строку в журнал событий рядом с файлом заявок (вне git; путь переопределяет `CLAIMS_LOG`).

### Исправлено до релиза (независимый QA 2.0.0)

- **Установщик: чужая команда в одной группе с нашей остаётся (R1).** Обновление заменяло всю группу вокруг нашей команды — соседний хук (например, аудит или страж секретов, дописанный рядом с нашим) молча пропадал, а сужённый `matcher` возвращался к `*`. Теперь заменяется только наш объект-команда, на своём месте; `matcher` группы и все чужие команды остаются. Наш дубль во второй группе (из другого клона) удаляется. Унаследовано от v1.10.0.
- **Установщик: `'` в пути клона больше не ломает хуки (R2).** Путь шёл в одинарные кавычки без экранирования, и клон в `Mike's tools` давал команды с синтаксической ошибкой и кодом 2 — блокировался каждый промпт и каждое сжатие. Теперь кавычка экранируется (`'\''`); `doctor.sh` и установщик читают её обратно. Унаследовано от v1.10.0.
- **Установщик: нужен python3, и проверяется он первым (Y1).** С jq, но без python3 установщик называл исправный файл настроек «invalid JSON», уже скопировав скиллы. Теперь и `install.sh`, и `hooks/install.sh` останавливаются с «python3 is required» до любой записи. Самим хукам по-прежнему хватает jq или python3.
- **Установщик: старый клон pf-handoff — наш (Y2).** Регистрация на `<каталог>/hooks/…` другого клона pf-handoff (в нём есть `install.sh` и `.claude-plugin/plugin.json` с именем `pf-handoff`, а в v1.10.0 и раньше — `skills/pf-handoff/SKILL.md`) переносится на этот клон со строкой `MOVED: <событие> <старый путь> → <новый путь>`, а не остаётся KEPT; `doctor.sh` на такую регистрацию печатает `WARN`. Копия без этого манифеста (мастерская автора) по-прежнему KEPT.
- **`sessionstart.sh`: на старте — перечень, поля обрезаны (Y3).** На свежем старте хук больше не говорит «прочитай HANDOFF и продолжи»: новый чат может быть о другой задаче, а файл — принадлежать параллельной сессии или прийти из чужого репозитория. Поля из файла (`task:`, ячейки реестра) идут в контекст не длиннее 120 знаков.
- **`sessionstart.sh`: печатает id сессии.** Каждый старт, резюме, сжатие и `/clear` заканчиваются строкой `Сессия: <первые 8 знаков> — это значение поля session_id в HANDOFF/реестре`, чтобы агент мог заполнить `session_id` в HANDOFF и реестре; шаблон и скилл говорят, откуда брать значение.
- **Тихий режим для дочерних процессов council.** С `PF_COUNCIL_RUN=1` в окружении (`council.sh` из pf-workflow ставит её запущенному CLI) `sessionstart.sh`, `context-guard.sh`, `precompact.sh` и `statusline.sh` ничего не печатают и выходят с 0; снимок для такого одноразового процесса не пишется.
- **Каталог HANDOFF игнорирует себя в git (Y4).** Когда `pf-handoff.sh --path` или хук снимка создают `.agents/runtime/handoff/`, они кладут в него `.gitignore` с `*` и `!.gitignore`: снимок хранит последние реплики человека дословно и не должен уезжать в коммит с `git add -A`.
- **README (Y5, Y6):** заметка о statusLine ведёт к **самому раннему** бэкапу настроек; удаление снимает только наши записи одной командой, а не восстанавливает бэкап, который откатил бы все поздние настройки; перечислены копии скиллов в `~/.codex/skills` и `~/.gemini/skills`.
- **`plugin.json` — версия 2.0.0 (Y7).**
- **В файлах дистрибутива нет имён клиентских проектов (Y8).** Правила, комментарии хуков и имя тестовой фикстуры их больше не упоминают; `sync-from-tools.sh` и `tests/run.sh` сверяют дерево с приватным стоп-листом, который лежит вне этого репозитория (`PF_PRIVATE_WORDS`; без него тест пропускается).
- **`context-guard.sh`: окно статус-строки важнее правила по имени модели (Y9).** Модель семейства 5 может работать с окном 200k; устаревшее состояние, записанное статус-строкой, теперь решает окно, а «семейство 5 ⇒ 1M» действует, только когда окна в состоянии нет. Окно, которое guard оценил сам, хранится с `window_guess: 1` и не принимается за число статус-строки.
- **`context-guard.sh`: файл состояния от v1.10.0 — не окно статус-строки (N2).** Старый guard писал в состояние свою догадку по алиасу из настроек (200000 для `opus`) без пометки, и после обновления сессия, продолженная на модели 1M, получала ложную финальную директиву при реальных 15 %. Теперь статус-строка и guard пишут `state_version: 2`; состояние без этого поля считается догадкой (как `window_guess: 1`), и действует правило семейства 5.
- **`.gitignore` появляется и в уже существующем каталоге HANDOFF (N3).** Хук снимка и `pf-handoff.sh` кладут самоигнорирующий `.gitignore` в существующий `.agents/runtime/handoff/`, где его нет (каталог есть у всех, кто работал на v1.10.0); существующий `.gitignore` не трогается, через симлинк на его месте запись не идёт. README, «Обновление»: как убрать из индекса снимки, закоммиченные раньше.
- **Установщик: чужой хук с нашим именем файла — громко (N4).** Оставленная регистрация `precompact.sh`/`sessionstart.sh`/`context-guard.sh`, рядом с которой нет наших скриптов, печатает `WARN: KEPT: … our <событие> hook is NOT installed` (`doctor.sh` — `WARN`, не `OK`); копия этих хуков (все четыре скрипта вместе) остаётся обычным `KEPT`. `--force` печатает `REPLACED: <событие> <старая команда> → <наш скрипт>` для каждой заменённой регистрации, а не заменяет молча.
- **Правила: протокол заявок — только там, где есть файл заявок (Y10).** Без `CLAIMS_FILE`/`TOOLS` или мастерской автора агент заявки не пишет и `ВНИМАНИЕ` не ждёт; где файл настроен, ничего не меняется. Инструменты мастерской в правилах помечены; новому файлу заявок нужен заголовок `## Живые заявки` (одного `touch` мало).

### Добавлено

- **Handoff на вехах.** `pf-handoff` переписывает HANDOFF на пяти вехах, на любой платформе (принята сводка задачи; запущен субагент или внешний процесс; перед внешним действием — push, deploy, тег; конец волны; перед долгим процессом): короткий снимок около 10 строк при заполнении окна ниже 50 %, полный `pf-handoff` при 50 % и выше или когда процент неизвестен. `skills/pf-handoff/scripts/pf-handoff.sh` помогает агентам без хуков: `--path` печатает активный HANDOFF (создаёт из шаблона, если его нет), `--short` печатает короткий снимок для заполнения, `--touch` обновляет `updated:`.
- **`hooks/secrets-guard.sh`** — хук `PreToolUse` на Bash, который отказывает на закрытом списке широких команд над секретами. Установщик его не регистрирует. Это заглушка-обёртка (shim): если рядом есть `pf-guard/hooks/secrets-guard.sh` (`PF_GUARD_HOME` или `repos/pf-guard` рядом с этим клоном), она запускает тот файл, иначе — собственное тело.
- **Правила (`docs/context-rules.ru.md`, обе версии):** что можно записывать в MEMORY.md (только слова человека или собственный вывод агента, никогда результат инструмента и никогда идентификаторы), межпроектный индекс решений, ритуал старта и финиша сессии, провенанс команды и запрет откатывать чужое по подозрению, протокол заявок выше и уровни сжатия по размеру окна.
- **`evals/`: 3 контрактных кейса** для `claude plugin eval` (`handoff-keeps-not-todo`, `resume-refuses-not-todo`, `resume-stops-on-stale-handoff`), каждый привязан к правилу текста скилла, с фикстурами из `scaffold.sh`, бесплатными грейдерами и отрицательным контролем. `evals/README.md` фиксирует первый полный прогон (3/3 кейса, 18 сессий, Δ 0 / +0,11 / 0): кейсы не различают текст правила — задокументировано, не исправлено. `.claude-plugin/plugin.json` — манифест только для `claude plugin validate`/`eval`; поле `hooks` в нём не объявлено, поэтому путь установки остаётся `install.sh`.
- **README:** блок «Обновление» (`cd <клон> && git pull && bash install.sh`), объяснение `KEPT`/`--force`, заметка о бэкапе настроек для тех, кто ставил версию до 2.0.0, и раздел «Для вашего ИИ-агента» — точные шаги установки, проверки, обновления и первого запуска, которые агент выполнит без догадок.
- **Тесты:** `tests/guard-cases.sh` (окно из модели, поправка на advisor, молчание для субагентов, первое пересечение второго порога), переписанный `tests/threshold-parity.sh`, расширенные пробы claims-check, кейсы установщика для KEPT/`--force`/таймаута и `actionlint` как необязательная часть CI.

## v1.10.0 — 2026-08-14

Снимок состояния перед каждым сжатием и протокол для сессий, которые друг друга не видят. Minor, не patch: здесь приезжают две настоящие новые возможности — ворота перед сжатием и проверка заявок на запись, — при этом формат HANDOFF, имена state-файлов и схема установки не тронуты (собственная граница проекта для major).

- **Новое: авто-снимок состояния и ворота, которые без него не пускают сжатие.** `autocheckpoint.sh` (новый хук — вызываемый, а не зарегистрированный) пишет `<проект>/.agents/runtime/handoff/<дата>-auto-<сессия>.md` из фактов, которые видно с диска: ветка, незакоммиченное, последние коммиты, открытые task-пакеты, живые HANDOFF-файлы, последние реплики человека из транскрипта, заполнение окна. `precompact.sh` вызывает его перед **каждым** сжатием — и автоматическим, и ручным `/compact` — и возвращает код 2 (документированное «блокирует сжатие»), если записать не удалось никуда. `context-guard.sh` делает то же на пороге t2 (по умолчанию 80%, следуя `context-budget.json` проекта) и сообщает агенту **факт**: снимок записан или нет. Снимок — страховочная сетка, а не `pf-handoff`: скрипт не умеет отличать доказанное от заявленного, смысловой чекпоинт по-прежнему за агентом.
- **Цена этих ворот, названная вслух** (и записанная теперь в доках на обоих языках): они умеют блокировать сжатие — это жёсткая остановка, а не предупреждение. Срабатывает, если снимок не записался ни в каталог проекта, ни в аварийный `~/.claude/context-state/handoff`; если рядом с `precompact.sh` нет `autocheckpoint.sh`; если в PATH нет ни `jq`, ни `python3` — без разбора JSON нет session_id, а значит нечем назвать файл снимка. Выходы, по порядку: выполнить `pf-handoff` руками; починить права на запись; поставить `jq` или `python3`; в крайнем случае убрать запись `PreCompact` из `settings.json` — вместе с блокировкой уйдёт и страховка. Каждая попытка попадает в журнал `~/.claude/context-state/compacts.log`, причина всегда идёт в stderr.
- **Сжатие запускает харнесс, и `doctor.sh` теперь говорит, в каком вы режиме.** Хук инициировать сжатие не может — такого поля вывода у хуков нет, — поэтому вторая половина замысла («сжатие на 80%») — это настройка `autoCompactWindow`, и считается она **в токенах, а не в процентах**. `doctor.sh` печатает её значение или сообщает, что сжатие произойдёт на пределе модели. Это никогда не ошибка, просто факт.
- **Новое: заявки на запись при параллельных сессиях — с настоящей проверкой вместо сниппета.** Сессии не видят команд друг друга, а «я не вижу оснований для этой правки» — не доказательство, что их нет. Заявки лежат в одном локальном файле машины; `skills/pf-handoff/scripts/claims-check.sh` отвечает ровно тремя состояниями — `ЗАНЯТО` (1), `СВОБОДНО` (0), `ВНИМАНИЕ` (2, «проверить не удалось») — и никогда молчанием. Обе стороны сравнения канонизируются по-настоящему (expanduser → абсолютизация → realpath → NFC → регистр, причём регистр складывается только там, где том действительно регистронечувствителен): у одного пути много записей, и строковое сравнение их молча пропускало. Со скриптом едет его собственная враждебная батарея `tests/claims-check-probes.sh` (54 пробы), которую переносит `sync-from-tools.sh`.
- **Починка: подхват HANDOFF на старте сессии работал только на macOS.** `sessionstart.sh` читал время правки через BSD-форму `stat -f %m`; на Linux это другая программа с тем же именем, каждый файл молча выпадал из списка, и выглядело это ровно как «живых HANDOFF-файлов нет». Теперь пробуется BSD-форма, затем GNU (`stat -c %Y`), и проверяется **результат**, а не код возврата: GNU-шный `stat -f` «успешно» печатает сведения о файловой системе.
- **Починка: закрытие ветки больше не угадывает, чей это worktree.** Если падала сама `orca worktree list`, конвейер возвращал код `grep`, а не Orca, отказ читался как «не под управлением Orca», и `git worktree remove` удалял управляемый worktree за её спиной. Референс теперь останавливается и говорит, что принадлежность неизвестна: четвёртое состояние, отказ в закрытую сторону вместо правдоподобной догадки.
- **Набор тестов снова говорит про ворота правду — и получил новую группу.** Старая матрица «хуки никогда не падают» требовала от `precompact.sh` тихого `rc=0` на мусорном stdin, чему ворота сознательно противоречат. `precompact.sh` вынесен в свою группу с более строгим контрактом: заблокировано **и громко** (код 2 плюс человекочитаемая причина), когда снимок записать не удалось; тихий `rc=0` и файл снимка на диске, когда удалось; плюс отрицательный контроль — тот же валидный вход в HOME без права записи обязан покраснеть. В составе набора идёт и уровень 1 `drift-check.sh` (этот репозиторий против свежего `sync-from-tools.sh`).

Находки независимого предрелизного QA — все закрыты до тега:

- **Критическая починка: на Debian/Ubuntu не работал ни один хук, а новые ворота блокировали каждое сжатие.** Установщик регистрировал хуки как `/bin/sh '<хук>'`. Claude Code исполняет эту команду системной оболочкой, поэтому шебанг `#!/bin/bash` не действовал: на macOS `/bin/sh` — это сам bash, и ничего не было видно, а на Debian/Ubuntu это dash, который наши скрипты прочитать не может — каждый хук умирал на первом же bash-изме с кодом 2. А 2 — это не «ничего не сделал»: для `PreCompact` это «сжатие заблокировано», для `UserPromptSubmit` — «промпт заблокирован и стёрт». Теперь регистрация называет интерпретатор явно (`bash '<хук>'`, ищется по `PATH` — значит годится и bash из Homebrew или Nix); если bash нет вовсе, обёртка сливает stdin и выходит с нулём: хуки самоотключаются, а не запирают сессию. Переписывать хуки на POSIX не стали: это 1500 строк bash, каждую будущую правку которых пришлось бы держать POSIX-совместимой без единой проверки, способной заметить это на macOS, — а назвать интерпретатор стоит одного слова и обратно не отваливается.
- **Починка: документированный путь обновления (`git pull && bash install.sh`) не чинил ничего.** Установщик умел только ДОБАВЛЯТЬ отсутствующую запись, поэтому машина со старой регистрацией держала её вечно — фикс выше не доехал бы ни до одного действующего пользователя. Теперь он переписывает СВОИ устаревшие записи (сверка по имени файла хука) и по-прежнему не трогает чужие; повторный запуск, как и раньше, байт-в-байт тот же.
- **Починка: `claims-check.sh` отвечал спокойным «держаний нет» из корня, которому не имел права верить.** При вызове по документированному пути `~/.claude/skills/pf-handoff/scripts/…` — куда установщик кладёт обычные копии, а не симлинки — правило «четыре уровня вверх» даёт корень мастерской `$HOME`; при существующем каталоге `~/.agents/runtime` спокойная ветка срабатывала поверх заведомо неверного корня. Теперь вычисленный корень ПРОВЕРЯЕТСЯ (в нём должен лежать каталог `skill-library/`), иначе ответ — `ВНИМАНИЕ` с названным выходом: задать `TOOLS` (или `CLAIMS_FILE`) один раз. Доки больше не обещают «находится без настройки» за пределами мастерской.
- **Починка: `sessionstart.sh` молча терял подхват HANDOFF, если в окружении нет `HOME`.** Под `set -u` голый `$HOME` убивал скрипт, обёртка глотала ошибку, и наружу это выглядело ровно как «живых шпаргалок нет». Теперь он использует `PF_EFFECTIVE_HOME`, как остальные три хука, — контракт v1.9.0, который этот хук пропустил.
- **Починка: пустой вход пропускал сжатие без снимка И без следа.** Он и сейчас пропускает (блокировка на «stdin не доехал» воссоздала бы тот самый клин из фикса про Debian), но попытка теперь пишется в журнал как `SKIPPED-empty-stdin`. Сессия субагента — осознанный случай «снимок не нужен» — пишется как `SKIPPED-subagent` вместо прежнего `OK ?`, которое читалось как «снимок сделан».
- **Текст блокировки стал английским** (с одной русской строкой-выжимкой) и больше не ссылается на внутренний номер правила, которого в дистрибутиве нигде нет. README на обоих языках наконец описывает ворота: что они делают, когда блокируют, что человек увидит и какие есть четыре выхода, — до сих пор README описывал хук версии v1.9.0, который «логирует каждый компакт», в первом же документе, который читает новый пользователь.
- **Новая группа тестов, закрывающая слепое пятно, за которым всё это пряталось**: сюита теперь берёт строку команды ИЗ `settings.json`, только что записанного установщиком, и исполняет её настоящей POSIX-оболочкой (`/bin/dash`, либо `/bin/sh` там, где это dash — на CI `ubuntu-latest` это так). Все остальные группы запускают хуки явным `bash` — именно поэтому зелёная матрица на ubuntu ничего не доказывала о том, как хуки запускаются на самом деле. Плюс отрицательный контроль: старая обёртка в той же оболочке обязана краснеть (она выходит с кодом 2), и пробы на обновление устаревшей записи и на подхват HANDOFF без `HOME`.
