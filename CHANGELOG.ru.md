# Журнал изменений

*[English version](CHANGELOG.md)*

Semver: ломающие изменения (формат HANDOFF-файла, имена state-файлов, контракт скиллов, схема установки) = major; новые возможности = minor; починки = patch.

## v1.6.0 — 2026-08-10

- **Конфигурируемая статус-строка** — `~/.config/pf-handoff/statusline.json` (опционален; дефолты воспроизводят v1.5.0 в точности): раскладка виджетов `line1`/`line2` по белому списку (`model`, `context`, `branch`, `session`, `weekly`, плюс новые `cost` и `duration`), `bar_width` (5–60), `bar_filled`/`bar_empty`, `separator` (пустая строка уважается), `colors: false` для чистого текста. Отсутствующий ключ `line1`/`line2` оставляет дефолт; явно пустой массив отключает строку. Цвета зон бара — из порогов *проекта* (`.agents/context-budget.json`). Полный справочник — в обоих README.
- Укреплено независимым QA-раундом №2 (80 проверок; находки закрыты до тега, по правилу релизов): числа с ведущим нулём («08») больше не гасят рендер и не теряют state; пользовательские символы бара идут через `ENVIRON` (без awk-интерпретации эскейпов/форматов); FIFO-конфиги не могут подвесить ни один хук (везде проверка регулярного файла); обход белого списка запятой в имени закрыт; глоб-расширение имён виджетов отключено; BOM-конфиги парсятся одинаково в jq- и python3-ветках; абсурдные значения `duration` скрывают виджет вместо отрицательного времени; дробные пороги проекта единообразно округляются вниз в обоих движках.

## v1.5.0 — 2026-08-10

- **Богатая двухстрочная статус-строка** (стиль ccstatusline, по-прежнему ноль зависимостей — чистый bash/awk): прогресс-бар контекста с цветами зон по порогам §13, токены/окно, git-ветка со счётчиком строк сессии и вторая строка с лимитами подписки — `Session % | Reset | Weekly % | Weekly Reset`. Сегменты мягко исчезают при отсутствии поля; проброс Orca и датчик state-файла не изменились.
- Укреплено по итогам независимого QA-раунда (82 сценария, 7 находок закрыты до релиза — по правилу релизов): нечисловые `used_percentage`/окно больше не обнуляют вывод и не теряют state; скалярные `.model`/`.rate_limits`/`.workspace` не ломают jq-ветку; гарантированный exit 0 даже без `$HOME`; инъекции управляющих символов (ANSI/U+001F/перевод строки) из строк payload вычищаются на экстракторе; сверхдлинные session id не оставляют tmp-мусор; нечитаемый прежний state не сбрасывает `announced`; проценты с точкой при любой локали.

## v1.4.2 — 2026-08-10

Фиксы независимого враждебного QA-раунда (64 сценария):

- **announced переживает обновления статус-строки** (существенный): statusline перезаписывал state сессии без поля `announced`, поэтому в реальном терминале каждое обновление сбрасывало «уже объявлено», и guard повторял одну и ту же директиву порога снова и снова. Теперь поле переносится при каждой перезаписи.
- **Установщик не удаляет чужие данные**: существующая реальная папка с именем нашего скилла заменяется только если её SKILL.md несёт наш `name:`; иначе — пропуск с сообщением (раньше — молчаливый `rm -rf`).
- **Дружба с dotfiles**: симлинк `~/.claude/settings.json` правится через свою цель — симлинк остаётся симлинком.
- **Строгий frontmatter**: строка `status: active` в теле файла больше не оживляет закрытую шпаргалку — учитывается только frontmatter.
- **Защита путей**: `session_id`/`agent_id` из входа хука санитизируются перед использованием как имена файлов (подделанный id вида `../evil` мог писать вне каталога состояния).
- Косметика: счётчики «до/после» установщика больше не печатают лишний ноль на свежем settings.json.

## v1.4.1 — 2026-08-10

- **Фикс**: HANDOFF-файл, созданный из шаблона «как есть», был невидим для SessionStart-хука — во frontmatter шаблона стоял inline-комментарий (`status: active   # active | closed`), а паттерн хука требовал конца строки сразу после «active». Паттерн теперь терпит хвостовые комментарии, а frontmatter шаблона очищен от них. Найдено standalone-тестом установки (после фикса 12/12 зелёных).

## v1.4.0 — 2026-08-10

Починка установки на чистых машинах — каждая проблема ниже воспроизведена в песочнице (свежий $HOME, анонимный клон с GitHub) и перепроверена зелёной (21/21) после фикса:

- **Новый корневой `install.sh`** — установка одной командой: копирует оба скилла (обычными копиями — клон после можно перемещать или удалять; поверхности `~/.codex`/`~/.gemini` — только если эти CLI есть, мусорных папок не создаём), регистрирует хуки, запускает doctor. Скиллы, уже существующие как *симлинки* (ваш собственный механизм управления), никогда не перезаписываются — пропуск с сообщением.
- **`hooks/install.sh`**: отсутствующий `~/.claude/settings.json` теперь создаётся (свежие машины), а не прерывает установку.
- **Фикс идемпотентности**: маркеры защиты от дублей искали имя каталога канона (`context-hooks/`), а в дистрибутиве каталог называется `hooks/` — повторный запуск установщика у внешних пользователей плодил дубли hook-записей. Маркеры теперь по имени файла.
- **`hooks/doctor.sh`**: тот же фикс имени каталога во всех проверках; Orca-проверки выполняются только если Orca реально установлена (`~/.orca/agent-hooks` существует) — машины без Orca получают чистый зелёный прогон вместо гарантированных провалов; машинозависимый порог «≥11 записей» заменён проверкой наличия.
- README (обе языковые версии): установка — одна команда `bash install.sh`; поведение при перемещении клона и пропуске симлинков задокументировано.

## v1.3.0 — 2026-08-10

- **Иерархии любой глубины проверены**: живой зонд с внуком подтвердил — каждый уровень вложенности (сын, внук, …) получает хуки со *своим* agent id и хранит плоский транскрипт в каталоге `subagents/` сессии, поэтому guard меряет каждый уровень отдельно. Добавлена find-страховка поиска транскрипта агента на случай смены раскладки каталогов harness'ом.
- **Правила стаи расширены**: реестр ведёт тот уровень, который запускает волну (оркестратор — в HANDOFF; субагент со своей волной — в своём файле прогресса); оборвавшийся уровень заменяется преемником, который продолжает по реестру и файлам результатов, не переспрашивая уже принятое.

## v1.2.0 — 2026-08-10

- **Правила стаи** (оркестратор с десятками субагентов в полёте): перед запуском волны — чекпоинт реестра «агент → задача → файл результата → статус» в HANDOFF; в промпте каждого агента — требование файлового выхода со сводкой ≤15 строк; на порогах окна новых волн не запускать, только принимать. ## v1.1.0 — 2026-08-09

- **Guard понимает субагентов**: вызовы инструментов субагента теперь меряются по транскрипту и окну *самого субагента* (путь вычисляется как `<каталог>/<сессия>/subagents/agent-<id>.jsonl`), под его собственным state-ключом `agent-<id>.json`. Раньше пороговое предупреждение могло быть «съедено» субагентом (расходуя родительский флаг `announced`), при этом показывая ему процент родителя — дезинформация для обеих сторон.
- **Пороги под проект**: `<проект>/.agents/context-budget.json` с `{"thresholds": [a, b, c]}` (три целых по возрастанию 1–99); нет файла или он кривой → дефолт 60/80/90. Смысл зон не меняется.
- **Критический фикс — разделитель полей**: разбор входа хуков переведён с табов на разделитель U+001F. Bash-`read` считает таб «схлопываемым пробелом», поэтому пустое поле (например, отсутствующий `agent_id` у родительских вызовов) сдвигало соседние значения в чужие переменные и могло полностью заглушить guard для родительских сессий.
- Документация: основной язык — английский, рядом полный русский перевод (`README.md`/`README.ru.md`, `docs/rules-section.md`/`.ru.md`, этот журнал); задокументирован инструмент-компаньон pf-workflow.

## v1.0.0 — 2026-08-09

Первый релиз. Собрано и обкатано в проекте владельца `optimize` (пилотные пакеты T-001…T-004, отчёт с замерами — в репозитории того проекта).

- Правила «Бюджет контекста и непрерывность сессий»: три слоя памяти, пороги 60/80/90% окна, эвристика «влезет ли», инструкция компактору, памятка человеку (`docs/rules-section*.md`).
- Скилл `pf-handoff`: чекпоинт/закрытие со сверкой доказанного, перезапись HANDOFF целиком, ≤120 строк; шаблон в `references/`.
- Скилл `pf-resume`: подхват по шпаргалке в новом чате / после `/clear`; переоткрытие закрытого файла по slug; автозакрытие шпаргалок завершённых задач.
- Хуки: `statusline.sh` (строка «⛽ N% · Xk/Y» + state-файл; телеметрия Orca пробрасывается, если Orca есть), `context-guard.sh` (пороговые вбросы + fallback по транскрипту), `sessionstart.sh` (автоподхват после автокомпакта с самопочинкой шпаргалки; ручной `/compact` → только подсказка «/pf-resume <slug>»; уборка state-файлов старше 14 суток), `precompact.sh` (лог компактов manual/auto).
- `install.sh` (идемпотентная установка в `~/.claude/settings.json` с бэкапом, пути от места клона) и `doctor.sh` (14 проверок).
- Замер: цена обвязки ≈182 токена/сессию в худшем случае; вне порогов вбросов нет.
