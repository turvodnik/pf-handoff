# pf-handoff — зафиксировать состояние, ничего не потеряв

Живое состояние задачи — HANDOFF-файл проекта `.agents/runtime/handoff/YYYY-MM-DD-<slug>.md` (§13). Скилл перезаписывает его целиком: свежим, точным, без мусора. Два режима: **чекпоинт** (работа продолжается) и **закрытие** (сессия завершается).

## Шаги

1. Определи файл: активный HANDOFF этой задачи (`status: active`) или создай новый по `references/handoff-template.md`; slug — номер тикета или тема.
2. Сверка перед записью: перечисли, что СДЕЛАНО и чем доказано (вывод команды, тест, коммит — §11). Недоказанное в «Состояние» не пишется — оно идёт в «Следующий шаг» или «Блокеры».
3. Перезапиши файл ЦЕЛИКОМ по шаблону, ≤120 строк: Цель / Состояние / Следующий шаг / Блокеры и вопросы / Ключевые файлы и решения / Не делать. Устаревшее из прошлой версии — в «Не делать» одной строкой либо прочь.
4. Обнови `updated` в frontmatter и статусы затронутых task-пакетов (§9).
5. Закрытие (сессия завершается или человек попросил): `status: closed`, запись в журнал §10 (решения и хендофф, не диффы), затем одна строка человеку — как продолжить: тот же чат — просто продолжай; новый — `/pf-resume <slug>`; терминал закрыт — `claude --continue`.

## Запрещено

Дописывать в конец вместо перезаписи; превышать 120 строк; писать в «Состояние» недоказанное; вставлять значения секретов (§5); коммитить HANDOFF в git (каталог в .gitignore — долговременная история живёт в журнале).
